# Ручная проверка: установка службы (шаг 7б) и переход с 0.6.8 (шаг 7в)

Автоматические тесты не ставят службу и не запускают установщик. Этот чек-лист проверяет то, что можно проверить
только на настоящей Windows: установку, службу, подключение без UAC, обновление и удаление. Устройство — в
[ARCHITECTURE.md](ARCHITECTURE.md#установка-шаг-7б) и [ADR-0001](adr/0001-privileged-service.md#шаг-7б--установка-и-интерфейс-через-службу-сделано-19102026).

Команды — для PowerShell. «Обычный терминал» — PowerShell без прав администратора, «админ-терминал» — «Запуск от
имени администратора». Отмечайте результат каждого пункта; при отказе сохраните журнал установки (см. «Где смотреть»).

## 0. Подготовка

1. Соберите тестовый установщик с версией выше текущей, чтобы его было легко отличить (версия в репозитории не
   меняется — это только параметр сборки):

   ```powershell
   .\build\Build.ps1 -Target Publish -Version 0.7.0
   .\build\Build.ps1 -Target Installer -Version 0.7.0
   ```

   Результат: `artifacts\installer\NothingVpnSetup.exe`. Либо скачайте артефакт ручного запуска workflow Release.
2. Сделайте копию данных (профили, подписки, настройки; копия читается только вашим пользователем — DPAPI):

   ```powershell
   Copy-Item "$env:LOCALAPPDATA\NothingVpn.Tray" "$env:USERPROFILE\Desktop\NothingVpn.Tray.backup" -Recurse
   ```

3. Запишите, что сейчас есть: число профилей и подписок, режим, DNS, rule-set, список приложений TUN, включён ли
   автозапуск:

   ```powershell
   Get-ItemProperty HKCU:\Software\Microsoft\Windows\CurrentVersion\Run -Name NothingVpn -ErrorAction SilentlyContinue
   Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select-Object ProxyEnable, ProxyServer
   ```

### Где смотреть

- Журнал установки: `%TEMP%\Setup Log <дата> #NNN.txt` пользователя, подтвердившего UAC. Последний:

  ```powershell
  Get-ChildItem $env:TEMP -Filter 'Setup Log*.txt' | Sort-Object LastWriteTime | Select-Object -Last 1 | Get-Content |
    Select-String 'service|Service|sc.exe|migration'
  ```

- Служба: `sc.exe query NothingVpn`, `sc.exe qc NothingVpn`, `sc.exe qfailure NothingVpn`; журнал событий —
  `Get-WinEvent -LogName Application -MaxEvents 30 | Where-Object ProviderName -eq NothingVpn | Format-List TimeCreated, Message`.
- Журнал клиента и службы — раздел «Диагностика» интерфейса.

## 1. Чистая установка

На машине (или под пользователем) без Nothing VPN. Если 0.6.8 стоит — сначала раздел 2 или удалите её с ответом
«Да — оставить папку».

1. Запустите `NothingVpnSetup.exe` двойным щелчком. **Ожидается:** UAC «Nothing VPN Setup»; страницы выбора
   каталога нет; есть задачи «ярлык на рабочем столе» и «автозапуск».
2. Отметьте «автозапуск», завершите установку с флажком «Запустить Nothing VPN».
3. Проверьте файлы и права каталога (запись — только администраторам и SYSTEM, у Users — `(RX)`):

   ```powershell
   Get-ChildItem 'C:\Program Files\NothingVpn' | Select-Object Name, Length
   icacls 'C:\Program Files\NothingVpn'
   ```

   **Ожидается:** `NothingVpn.Desktop.Wpf.exe`, `NothingVpn.Service.exe`, `sing-box.exe`, `wintun.dll`, `unins000.*`, `*.pdb`.
4. Служба:

   ```powershell
   sc.exe query NothingVpn      # STATE : 4  RUNNING
   sc.exe qc NothingVpn         # BINARY_PATH_NAME в кавычках, START_TYPE AUTO_START, SERVICE_START_NAME LocalSystem
   sc.exe qfailure NothingVpn   # RESET_PERIOD 86400, RESTART -- 5000 / 10000 / 60000
   ```

5. Данные службы — только SYSTEM и администраторы, без наследования:

   ```powershell
   icacls "$env:ProgramData\NothingVpn"
   ```

   Из обычного терминала `Get-ChildItem "$env:ProgramData\NothingVpn"` должен давать «Отказано в доступе».
6. Интерфейс запущен **без** прав администратора: в Диспетчере задач → «Подробности» включите столбец «С повышенными
   правами» — у `NothingVpn.Desktop.Wpf.exe` «Нет». На главной странице: «Обычный пользователь».
7. Ярлыки — общие: `Test-Path "$env:ProgramData\Microsoft\Windows\Start Menu\Programs\Nothing VPN\Nothing VPN.lnk"` → `True`.
8. Автозапуск указывает на новый exe:
   `(Get-ItemProperty HKCU:\Software\Microsoft\Windows\CurrentVersion\Run).NothingVpn` →
   `"C:\Program Files\NothingVpn\NothingVpn.Desktop.Wpf.exe"`.
9. В «Параметры → Приложения» одна запись «Nothing VPN» с новой версией.
10. Перезагрузите компьютер: служба запущена (`sc.exe query NothingVpn`), интерфейс стартовал из автозапуска,
    подключение работает.

## 2. Установка поверх 0.6.8 (вручную)

Установлена 0.6.8 (per-user, `%LOCALAPPDATA%\Programs\NothingVpn`), в ней есть профили, подписка, нестандартные
настройки и, желательно, включён автозапуск.

1. Закройте 0.6.8 (трей → «Выход»). Если оставить открытой, установщик попросит её закрыть.
2. Запустите новый `NothingVpnSetup.exe`, подтвердите UAC, завершите установку.
3. Старая копия убрана, данные целы:

   ```powershell
   Test-Path "$env:LOCALAPPDATA\Programs\NothingVpn"                    # False (или пустой каталог/занятые файлы — см. журнал)
   Test-Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\{A2D610D2-2A69-4D7A-9B06-6C0B4E5F5C87}_is1'   # False
   Test-Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\{A2D610D2-2A69-4D7A-9B06-6C0B4E5F5C87}_is1'   # True
   Get-ChildItem "$env:LOCALAPPDATA\NothingVpn.Tray"                    # state.json, profiles.json, subscriptions.json, rulesets\ на месте
   Test-Path "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Nothing VPN"   # False — старые личные ярлыки удалены
   (Get-ItemProperty HKCU:\Software\Microsoft\Windows\CurrentVersion\Run).NothingVpn   # если автозапуск был — новый путь
   ```

   В журнале установки: `User install migration (--migrate-user-install) -> 0` (2 — часть файлов была занята).
4. В интерфейсе те же профили, подписки, активный профиль, режим, DNS, rule-set и приложения TUN, что в пункте 0.3.
5. В «Приложениях» одна запись «Nothing VPN».

## 3. Служба и проверка канала

1. `sc.exe query NothingVpn` → `RUNNING`. Имя канала занято службой:
   `[System.IO.Directory]::GetFiles('\\.\pipe\') | Select-String 'NothingVpn.Service'`.
2. В «Диагностике» после старта интерфейса нет предупреждения «Служба Nothing VPN недоступна».
3. Проверку подлинности (сообщение «Служба Nothing VPN не прошла проверку подлинности…» при подмене сервера канала)
   вручную **не** проверять: она покрыта `ServiceChannelTests` (сервер, созданный процессом пользователя, отклоняется
   без отправки данных).

## 4. Подключение без UAC: proxy, tun, tun_apps

Для каждого режима:

1. Запомните PID интерфейса: `(Get-Process NothingVpn.Desktop.Wpf).Id`.
2. Выберите профиль и режим, нажмите «Подключить». **Ожидается:** UAC не появляется, PID интерфейса тот же,
   статус «Подключено». В Диспетчере задач `sing-box.exe` работает от имени «СИСТЕМА» (столбец «Имя пользователя»).
3. Проверка трафика:
   - **proxy**: `Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select-Object ProxyEnable, ProxyServer`
     → `1`, `127.0.0.1:<порт>`; браузер открывает сайты; `curl.exe -s -x http://127.0.0.1:<порт> https://api.ipify.org` — адрес VPN;
   - **tun**: `curl.exe -s https://api.ipify.org` — адрес VPN; системный прокси не включён;
   - **tun_apps**: выбранное приложение ходит через VPN, остальные (`curl.exe -s https://api.ipify.org`) — напрямую.
4. «Диагностика → Проверить подключение» проходит; в журнале есть строки sing-box (пришли из службы).
5. «Отключить»: статус «Отключено», `sing-box.exe` нет, в режиме proxy `ProxyEnable`/`ProxyServer` вернулись к
   значениям из пункта 0.3.
6. Rule-set: включите пользовательский или встроенный rule-set и подключитесь в tun — подключение проходит (rule-set
   передаются службе содержимым).

## 5. Перезапуск интерфейса при активном VPN

Выход из трея отключает VPN намеренно, поэтому интерфейс завершаем принудительно:

1. Подключитесь в режиме **proxy**. Затем в обычном терминале:

   ```powershell
   Stop-Process -Name NothingVpn.Desktop.Wpf -Force
   Get-Process sing-box                                     # работает — VPN пережил интерфейс
   Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select-Object ProxyEnable, ProxyServer   # прокси включён
   ```

2. Запустите Nothing VPN из меню «Пуск». **Ожидается:** в течение ~3 с статус «Подключено», тот же профиль и режим,
   трей — «подключено», сайты открываются (прокси не сбросился).
3. «Отключить»: `sing-box` остановлен, `ProxyEnable`/`ProxyServer` — исходные (как в пункте 0.3).
4. Повторите для **tun**: после перезапуска «Подключено», отключение работает.

## 6. Остановка службы при активном VPN

1. Подключитесь в режиме **proxy**. В админ-терминале: `Stop-Service NothingVpn`.
   **Ожидается:** через 1–2 с интерфейс показывает «Отключено», `sing-box` нет, `ProxyEnable`/`ProxyServer` исходные
   (интернет работает без VPN).
2. Нажмите «Подключить». **Ожидается:** ошибка «Служба Nothing VPN не отвечает. Запустите службу «Nothing VPN»
   (services.msc) или переустановите приложение.», UAC не появляется, приложение не перезапускается.
3. `Start-Service NothingVpn` → «Подключить» работает.
4. Восстановление при сбое: в админ-терминале `Stop-Process -Name NothingVpn.Service -Force`. **Ожидается:**
   интерфейс показывает «Отключено»; через ~5 с `sc.exe query NothingVpn` снова `RUNNING`; подключение работает.

## 7. Обновление из интерфейса

Интерфейс ставит обновление, только если на GitHub вышел релиз новее установленного, поэтому полностью этот пункт
проверяется после выпуска версии со службой — на следующем за ней релизе. До этого проверяется тот же способ запуска
установщика, которым пользуется интерфейс: процесс без прав, `UseShellExecute=false`, тихие аргументы.

С шага 8 помощника PowerShell нет ([UPDATE-HANDOFF.md](UPDATE-HANDOFF.md)): после загрузки интерфейс проверяет файл
и свои права, штатно закрывается (VPN отключается, мьютекс освобождается) и только затем сам запускает установщик.
Эмуляция ниже повторяет именно этот порядок: сначала выход, потом запуск.

**Эмуляция (до релиза).** Установлена версия из раздела 1 или 2. Соберите установщик ещё раз (можно с
`-Version 0.7.1`), подключитесь в режиме proxy, закройте интерфейс через трей → «Выход» (так делает интерфейс перед
обновлением). Запомните PID службы:

```powershell
(Get-CimInstance Win32_Service -Filter "Name='NothingVpn'").ProcessId
```

В **обычном** терминале:

```powershell
$info = [System.Diagnostics.ProcessStartInfo]::new((Resolve-Path .\artifacts\installer\NothingVpnSetup.exe).Path,
  '/SILENT /SP- /SUPPRESSMSGBOXES /CLOSEAPPLICATIONS /NORESTART')
$info.UseShellExecute = $false
$p = [System.Diagnostics.Process]::Start($info); $p.WaitForExit(); $p.ExitCode
```

**Ожидается:** появляется UAC; после подтверждения — окно прогресса без вопросов; код выхода `0`; PID службы
другой (`sc.exe query NothingVpn` — `RUNNING`); интерфейс открылся сам, **без** повышенных прав; профили и настройки
на месте; «Подключить» в tun работает без UAC. Отказ в UAC → установка не выполнена, старая версия и служба работают
(код выхода ненулевой).

**Настоящее обновление (после релиза следующей версии).** Подключитесь (лучше в tun), в интерфейсе «Обновить» →
статус «Закрытие приложения и запуск установщика…» → VPN отключается, интерфейс и значок в трее исчезают → UAC →
тихая установка → интерфейс открывается снова, без прав (в Диспетчере задач у `NothingVpn.Desktop.Wpf.exe` столбец
«С повышенными правами» — «Нет»). Критерии те же, плюс:

- процесса `powershell.exe` при обновлении не появляется;
- отказ в UAC → установки нет, старая версия и служба работают; интерфейс не запущен — откройте его вручную, данные
  и настройки на месте.

**Защитная проверка повышения.** Запустите интерфейс правой кнопкой → «Запуск от имени администратора», раздел
обновлений → «Обновить» (когда доступно). **Ожидается:** сообщение «Интерфейс запущен от имени администратора…
Закройте Nothing VPN, запустите его обычным способом…»; ничего не скачивается, VPN не отключается, интерфейс не
закрывается.

## 8. Деинсталляция

1. «Параметры → Приложения → Nothing VPN → Удалить» → UAC → вопрос «Сохранить пользовательские данные?».
   Ответ «Да — оставить папку».
2. **Ожидается:**

   ```powershell
   sc.exe query NothingVpn                         # 1060: служба не установлена
   Test-Path 'C:\Program Files\NothingVpn'         # False
   Test-Path "$env:ProgramData\NothingVpn"         # False
   Test-Path "$env:LOCALAPPDATA\NothingVpn.Tray"   # True — данные сохранены
   (Get-ItemProperty HKCU:\Software\Microsoft\Windows\CurrentVersion\Run).NothingVpn   # пусто
   Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select-Object ProxyEnable   # не оставлен включённым
   ```

   Ярлыков в меню «Пуск» и на рабочем столе нет.
3. Установите снова, удалите с ответом «Нет — удалить вместе с приложением» → `%LOCALAPPDATA%\NothingVpn.Tray` удалён.
   Верните данные из копии: `Copy-Item "$env:USERPROFILE\Desktop\NothingVpn.Tray.backup" "$env:LOCALAPPDATA\NothingVpn.Tray" -Recurse`.
4. Тихая деинсталляция (`& 'C:\Program Files\NothingVpn\unins000.exe' /SILENT` в админ-терминале) удаляет данные без
   вопроса — как раньше. Проверять только с копией данных.

## 9. Необязательно: другой администратор подтверждает UAC

Под стандартным пользователем без прав администратора запустите установщик и введите в UAC пароль администратора.
**Ожидается:** старая per-user копия стандартного пользователя удалена, его данные и автозапуск — как в разделе 2
(миграция работает от имени того, кто запустил установщик). Ограничение: если установщик запущен через «Запуск от
имени администратора», миграция идёт в профиле администратора — тогда старую копию пользователя удалите её
деинсталлятором с ответом «Да — оставить папку». Деинсталлятор убирает автозапуск и (по ответу) данные только у
того, кто его запустил.

## Шаг 7в: обновление 0.6.8 через встроенный механизм

Цель — убедиться, что клиенты ≤ 0.6.8 обновятся на per-machine установщик своим встроенным обновлением без
промежуточного релиза (ADR-0001, «Переход со старых версий»). 0.6.8 запускает установщик так: скачивает его в
`%TEMP%\NothingVpn\`, выходит (отключая VPN), помощник PowerShell с **неповышенным** токеном вызывает
`Process.Start(UseShellExecute=false)` с `/SILENT /SP- /SUPPRESSMSGBOXES /CLOSEAPPLICATIONS /NORESTART`. Открытый
вопрос — появится ли UAC у самоповышающегося установщика в тихом режиме.

### Подготовка

Стоит 0.6.8 из релиза (per-user), данные скопированы (пункт 0.2), записано состояние (пункт 0.3).

### А. Эмуляция без публикации релиза

Проверяет ровно последний шаг 0.6.8. Закройте 0.6.8 через трей → «Выход» и в **обычном** терминале выполните команду
из раздела 7 («Эмуляция») с новым установщиком. Повторите на чистой 0.6.8 после того, как она была подключена в TUN
(повышенный клиент 0.6.8 запускает установщик тем же неповышенным токеном, поэтому команда та же; важно, что
повышенный клиент перед этим вышел и отключил TUN).

### Б. Настоящее обновление

0.6.8 видит только последний релиз `EXTRBXY/vpn`, поэтому проверка возможна только опубликованным релизом. Порядок:
опубликовать версию со службой (тег `v0.7.0`), сразу обновить свою 0.6.8 из интерфейса — в обычном режиме и, на
второй машине или после отката, из клиента, подключённого в TUN. При провале — удалить релиз на GitHub
(клиенты проверяют обновления раз в ~23,5 ч, окно небольшое) и перейти к плану Б ниже.

### Критерии успеха (А и Б)

1. После выхода 0.6.8 появляется **UAC** «Nothing VPN Setup» (а не тишина и не ошибка).
2. После подтверждения установка доходит до конца без вопросов: `sc.exe query NothingVpn` → `RUNNING`.
3. Старая копия удалена, данные и автозапуск перенесены — проверки раздела 2, пункт 3.
4. Интерфейс новой версии запустился сам, от имени пользователя, **без** повышенных прав.
5. Профили, подписки и настройки — как в пункте 0.3; подключение proxy и tun работает без UAC.
6. Отказ в UAC: установка не выполнена, 0.6.8 остаётся рабочей (запускается из меню «Пуск», данные целы).

### Если не прошло

- **UAC не появился / установщик сразу завершился** (код выхода ненулевой, в `%TEMP%` нет журнала с этапами
  установки): нужен **промежуточный релиз** — последняя per-user версия (например, 0.6.9), которая запускает
  установщик так, чтобы Windows показала UAC (ShellExecute из процесса с обычными правами), и затем уже версия со
  службой. Права передаются только через явное согласие в UAC, не по наследству. Это решает пользователь;
  зафиксируйте результат в ADR-0001.
- **UAC есть, но установка падает или зависает**: сохраните журнал установки и журнал событий (служба), не
  выпускайте релиз; это ошибка установщика, а не способа запуска.
- **Всё установилось, но интерфейс не открылся сам**: не блокирует релиз — пользователь запустит его из меню «Пуск»;
  запишите в ADR как известное ограничение.
- **Данные пропали**: остановитесь, восстановите из копии (`Copy-Item … -Recurse`), сохраните журнал установки —
  это блокирующая ошибка миграции.

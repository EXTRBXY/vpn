# Проверка исправлений WPF UI

## Что исправлено

- Удаление TUN-приложения меняет одну строку, сохраняет остальные пути и обновляет выделение. Перечисления материализуются до очистки коллекции.
- Нормализация сохранённых путей больше не удаляет временно недоступные `.exe`. Поиск установленных приложений проверяет существование файлов отдельно.
- Все поля редактора, приложения и правила записываются одной операцией `UpdateState`. Ошибка валидации не сохраняет часть настроек; фоновые поля обновлений и состояния соединения сохраняются.
- Навигация сохраняет черновик настроек. Правила редактируются как копии сохранённых данных. Изменение режима на главном экране записывает только режим.
- MTU проверяется по введённому тексту. Пользовательский DNS корректно сбрасывает обозначение пресета; системный DNS отключает поля DoH. Значение стека `system` отображается в списке.
- Кнопка сохранения и сообщения закреплены под прокручиваемой страницей. Ошибки не исчезают по таймеру. Действия без выделения отключены.
- Каждая строка правил получает отдельный список действий. Флажки работают без входа в режим редактирования; Delete не удаляет строки в обход обработчиков.
- Загрузка правил фиксирует исходную строку и блокирует конфликтующие действия. Отсутствующий локальный файл загружается без условного запроса по старому ETag. Метаданные остаются в черновике до сохранения.
- Удаление файлов правил выполняется после успешного сохранения их отключения/удаления. При ошибке записи файлы остаются; ошибки удаления сообщаются отдельно и допускают повторную попытку.
- Обновление коллекции профилей не записывает временное пустое выделение. Подтверждённое удаление профиля/подписки использует ID из диалога, даже если фоновое обновление сменило выделение.
- Подключение из трея и основного окна имеет общую защиту от повторного запуска. Выход во время подключения дожидается его завершения и отключает VPN.
- Проверка обновлений и установка взаимно исключаются. Ошибки поиска приложений, подписок, работы с файлами и буфером обмена обрабатываются в интерфейсе. Закрытие окна поиска отменяет загрузку.

## Автоматическая проверка

`SettingsViewModelTests` использует реальные контроллеры, сервис настроек и политику путей с изолированным хранилищем. Покрыты удаление каждой позиции и всего списка, повторное открытие, дубликаты, несуществующие пути, навигация, DNS, единая запись, ошибки MTU/DNS/диска, удаление файлов и смена выделения при загрузке.

`WpfSettingsBindingTests` создаёт настоящие WPF-контролы и тему на STA-потоке. Проверяет двусторонние привязки, удаление выбранной строки, текст MTU, независимые действия правил, сохранение, обновление привязанного списка профилей, переходы между страницами, команды трея и выход во время подключения. Реальный VPN при этом не запускается.

Запуск: `dotnet test NothingVpn.sln -c Release`. Для уже восстановленных зависимостей доступны `--no-restore` и, после сборки, `--no-build`.

## Ручная проверка перед релизом

1. Добавить несколько реальных приложений, удалить среднее, сохранить, перезапустить клиент и проверить оставшиеся пути.
2. Изменить настройки, перейти на главную и обратно, затем сохранить. Проверить длинные списки и масштаб Windows 125–200%.
3. Подключить прокси, полный TUN и TUN приложений; проверить трафик выбранного приложения и переподключение после изменения настроек.
4. Проверить UAC, установку обновления, трей, системные диалоги и переключение светлой/тёмной темы в интерактивном Windows-сеансе.

Автоматические проверки WPF не заменяют проверку реального трафика, UAC, установки обновлений и визуальной доступности при разных DPI.

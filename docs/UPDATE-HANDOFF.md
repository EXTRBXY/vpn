# Запуск установщика обновления

> С шага 8 интерфейс никогда не повышен, поэтому прежний механизм передачи обновления из повышенного TUN-клиента
> (помощник PowerShell, неповышенный токен рабочего стола, протокол `READY/COMMIT/COMMITTED`) удалён. Его краткое
> описание — в конце, раздел «История».

Обновление доступно одной кнопкой: интерфейс скачивает установщик, закрывается штатным способом и запускает его.
Per-machine установщик (`PrivilegesRequired=admin`, манифест `asInvoker`) сам запрашивает UAC, ставит обновление
и запускает интерфейс снова от имени исходного пользователя (`[Run]` с `runasoriginaluser`).

## Последовательность

1. **Проверки до выхода** (`InstallerLaunchService.EnsureLaunchAllowed` перед загрузкой и `Prepare` после неё):
   процесс интерфейса не повышен, имя файла — `NothingVpnSetup.exe` или `NothingVpnSetup-*.exe`
   (`InstallerFilePolicy`), файл существует. Ошибка здесь показывается в разделе обновлений, VPN не отключается.
2. **Штатный выход** (`App.ExitThenLaunch`): VPN отключается (`StopForExitAsync`), останавливаются таймеры, убирается
   трей, освобождается мьютекс `Global\NothingVpn.Desktop.Wpf`.
3. **Запуск установщика** (`InstallerLaunchService.Launch`): проверки повторяются, установщик запускается
   `Process.Start` с `UseShellExecute=false` и аргументами `/SILENT /SP- /SUPPRESSMSGBOXES /CLOSEAPPLICATIONS
   /NORESTART`. Затем окно закрывается и процесс завершается.

Почему установщик запускается после освобождения мьютекса, а не до выхода: мьютекс интерфейса — `AppMutex`
установщика. В тихом режиме с `/SUPPRESSMSGBOXES` Inno Setup на вопрос «приложение запущено» отвечает «Отмена» и
прерывает установку, а не ждёт. Если запустить установщик до выхода, исход зависел бы от того, кто быстрее: пользователь
в окне UAC или выход интерфейса (при отключённом запросе UAC установщик почти наверняка застал бы мьютекс). Освобождение
мьютекса до запуска убирает эту гонку без помощника, который ждёт выхода. `CloseApplications` остаётся страховкой
для файлов в `{app}`, которые ещё держит завершающийся процесс.

Цена: если запуск установщика не удался уже после выхода (файл удалён антивирусом, отказ `CreateProcess`), VPN
уже отключён — интерфейс показывает сообщение «Не удалось запустить установщик обновления… Запустите Nothing VPN
снова» и пишет ошибку в журнал. Если пользователь отменил UAC, установщик завершается, интерфейс нужно запустить
вручную — так было и с помощником.

## Граница безопасности

- **Нет наследования повышенных прав.** Установщик получает токен интерфейса. Интерфейс в релизе не повышается; если
  его всё же запустили «от имени администратора», `EnsureLaunchAllowed` отказывает (`Environment.IsPrivilegedProcess`)
  с просьбой запустить клиент обычным способом. Запасного запуска с повышением нет.
- **Нет ShellExecute.** `UseShellExecute=false`: нет `runas`, ассоциаций файлов и автоматического повышения по
  манифесту. Подменённый файл не получает прав больше, чем у пользователя, — а их у процесса, способного писать в
  `%TEMP%` пользователя, и так столько же. Повышение даёт только UAC самого установщика, в котором Windows показывает
  издателя и путь.
- **Аргументы — данные.** Путь — `FileName`, тихие аргументы — отдельные элементы `ArgumentList`; ничего не
  подставляется в командную строку оболочки или скрипт.
- **Окружение.** Переменные `NOTHINGVPN_*` (например, `NOTHINGVPN_ENGINE=inprocess` разработчика) установщику и
  перезапущенному им интерфейсу не передаются.
- **Источник файла не меняется:** загрузка только из allowlist GitHub-хостов по https с проверкой финального URL
  (`InstallerDownloadUrlValidator`), см. [SECURITY.md](SECURITY.md#входные-данные-из-сети).

## Ограничения

- Это защита от наследования прав, а не проверка подлинности установщика. Подпись/доверенный хеш — отдельная задача
  (отложена, [SECURITY.md](SECURITY.md#входные-данные-из-сети)).
- Между `Prepare`/`Launch` и стартом процесса файл в `%TEMP%` теоретически может подменить процесс того же
  пользователя — без выигрыша в правах (см. выше).

## Проверка

- Автоматически: `InstallerLaunchServiceTests` (отказ при повышенном процессе без запуска, прямой запуск без
  ShellExecute с тихими аргументами, отклонение чужих имён и отсутствующего файла, пути с метасимволами остаются
  данными, переменные `NOTHINGVPN_*` не передаются) и `UpdateViewModelTests` (проверки до выхода, запуск — только
  после выхода, ошибка проверки не закрывает интерфейс).
- Вручную: [SERVICE-INSTALL-CHECKLIST.md, раздел 7](SERVICE-INSTALL-CHECKLIST.md#7-обновление-из-интерфейса).
  Отдельных desktop-тестов (`build/Test-UpdateHandoff.ps1`) больше нет.

## История

До шага 8 (версии ≤ 0.6.8 и сборки шагов 7а–7б) TUN требовал повышенного интерфейса, а установщик лежал в
изменяемом `%TEMP%`. Чтобы повышенный клиент не передал права подменённому установщику, `WindowsUserProcessLauncher`
запускал фиксированный скрипт Windows PowerShell (`InstallerUpdateWorker`) с копией неповышенного токена рабочего
стола, проверял его токен, обменивался с ним `READY/COMMIT/COMMITTED` по каналу со случайным именем, и уже помощник,
дождавшись выхода клиента, запускал установщик. Проверка реализации (31.08.2026) и desktop-тесты
`WindowsUpdateHandoffTests` прошли в обычном и повышенном контекстах. С переходом на службу (ADR-0001) повышенного
клиента не стало, и весь этот механизм удалён вместе с тестами.

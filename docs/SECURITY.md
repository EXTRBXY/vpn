# Безопасность

Сводка защитных механизмов и известных ограничений. Механизм обновления из повышенного клиента описан отдельно в
[UPDATE-HANDOFF.md](UPDATE-HANDOFF.md). Тесты-регрессии: `SecurityRegressionTests`, `DpapiJsonFileTests`,
`InstallerLaunchServiceTests`, `InstallerFilePolicyTests`, `SubscriptionHttpFetcherTests`, `WindowsUpdateHandoffTests`.

## Секреты

| Данные | Защита |
| --- | --- |
| UUID, ключи REALITY, URL подписок | `profiles.json`, `subscriptions.json` под DPAPI CurrentUser |
| Настройки и снимок системного прокси | `state.json` под DPAPI |
| Конфиг sing-box | **открытый текст** в `configs\` на время сессии; удаляется при остановке |
| Журнал | `LogRedactor` маскирует GUID, `vless://…`, путь после `/sub/`, `pbk=`, `sid=`, `uuid=`, `token/password/secret/api_key=`, `Authorization: Bearer` |

Правило проекта: никогда не логировать ключи, UUID, токены, приватные адреса в открытом виде. Любой новый источник
строк в журнал должен проходить через `InMemoryLogStore.AppendStructured` (он вызывает редактор).

Ограничение редактора: адрес VLESS-сервера и URL подписок без сегмента `/sub/` не маскируются.

## Входные данные из сети

- **Подписки** (`SubscriptionHttpFetcher`): только `https` (`SubscriptionUrlValidator`), без системного прокси,
  тело ≤ 4 МиБ (проверяется и `Content-Length`, и фактические байты), общий тайм-аут 90 с. Принимаются только
  `vless://`; каждая ссылка строго валидируется парсером.
- **Rule-set**: только встроенные URL из кода; имя файла не может содержать каталоги, `..`, абсолютный путь;
  обязателен `.srs`. Содержимое `.srs` не проверяется — его разбирает sing-box.
- **Обновления**: GitHub API → `browser_download_url` только с `github.com`, `objects.githubusercontent.com`,
  `release-assets.githubusercontent.com`, имя ассета `NothingVpnSetup.exe`, только https; финальный URL после
  редиректов проверяется повторно (`InstallerDownloadUrlValidator`). Запускаемый файл должен называться
  `NothingVpnSetup.exe` или `NothingVpnSetup-*.exe` (`InstallerFilePolicy`).

**Не реализовано:** проверка подписи или SHA-256 установщика клиентом. Release публикует
`NothingVpnSetup.exe.sha256`, но клиент его не использует. Целостность обновления держится на HTTPS и allowlist хостов.

## Привилегии

- Клиент запускается без прав администратора. TUN требует повышения: процесс перезапускается через `runas` с
  `--takeover`, старый процесс завершается (см. ARCHITECTURE.md).
- Повышенный клиент остаётся повышенным до выхода. Обновление из него запускается через проверенный
  неповышенный токен рабочего стола (`WindowsUserProcessLauncher`), без запасного повышенного пути.
- `sing-box.exe` в TUN-режиме работает с правами клиента (администратор).

### Известный риск: исполняемые файлы в пользовательском каталоге

Установщик ставит приложение в `%LOCALAPPDATA%\Programs\NothingVpn` (`PrivilegesRequired=lowest`). Каталог доступен на
запись любому процессу текущего пользователя. При TUN-подключении повышенный клиент запускает `sing-box.exe` и
загружает `wintun.dll` из этого каталога, а сам повышается из того же места. Локальный процесс без прав
администратора может подменить эти файлы и получить выполнение с повышенными правами при следующем TUN-подключении,
которое пользователь подтвердит в UAC.

Дополнительно `SingBoxRunner.ResolveSingBoxExePath` ищет `sing-box.exe` в `bin\`, в пяти родительских каталогах
и в каталоге установки — это удобно при разработке, но расширяет круг мест, откуда может быть взят бинарник.

Варианты решения — установка в `Program Files` (per-machine) или проверка подписи/хеша `sing-box.exe` перед запуском
с повышенными правами. Решение требует отдельного обсуждения: оно меняет модель установки и обновления.

## Межпроцессное взаимодействие

- Канал single-instance `NothingVpn.Desktop.Wpf.pipe`: ACL только для SID текущего пользователя; передаются только
  аргументы командной строки, которые разбирает `StartupOptions` (режим, профиль, `--start`). Любой процесс этого
  пользователя может инициировать подключение выбранным профилем.
- Канал обновления: случайное имя, ACL текущего пользователя, проверка PID сервера и времени старта родителя.

## Системные изменения

- WinINET-прокси меняется только в `proxy`-режиме; исходное значение сохраняется в `state.json` и восстанавливается
  при отключении, при падении sing-box и при следующем старте клиента (`RecoverStaleRuntimeState`).
- `sing-box` привязан к Job Object с `KILL_ON_JOB_CLOSE`: при аварийном завершении клиента sing-box тоже завершается.
- Отключение выполняется `Kill` дерева процессов, без штатной остановки sing-box. Корректность очистки маршрутов
  `auto_route` после принудительного завершения стоит проверять отдельно при изменении этой логики.

## Сетевые запросы самого клиента

| Запрос | Прокси |
| --- | --- |
| Подписки, rule-set, GitHub API | явно без прокси (`UseProxy = false`) |
| Скачивание установщика | системный прокси по умолчанию — при активном proxy-режиме идёт через VPN |
| Диагностика proxy-режима | через `127.0.0.1:{port}` |
| Диагностика TUN | без прокси; в `tun_apps` идёт напрямую, так как процесс клиента не в списке |

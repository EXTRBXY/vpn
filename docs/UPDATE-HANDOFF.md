# Обновление из повышенного TUN-клиента

Обновление остаётся доступно одной кнопкой. Клиент скачивает установщик, подготавливает обычный пользовательский процесс и получает подтверждение его готовности. Только после этого клиент завершает работу штатным способом, включая остановку VPN. Вспомогательный процесс ждёт фактического завершения клиента и запускает установщик с прежними параметрами тихой установки.

## Граница безопасности

Ранее изменяемый файл `%TEMP%/NothingVpn/NothingVpnSetup-<version>.exe` запускался через отложенную команду с правами клиента. Если локальный процесс мог подменить файл, повышенный клиент мог передать ему права администратора. Возможность подмены зависит от фактических ACL и контекста Windows; в первоначальном аудите она не была воспроизведена.

`WindowsUserProcessLauncher` проверяет пользователя, сеанс, уровень целостности и признак повышения. Для повышенного клиента используется копия обычного токена процесса рабочего стола. Созданный процесс сначала приостановлен: его токен повторно проверяется до выполнения кода. Нет запасного запуска с повышенными правами, `runas`, поиска через `COMSPEC` или ассоциации файлов.

Системный Windows PowerShell запускается по абсолютному пути без профиля и без изменения ExecutionPolicy. Код вспомогательного процесса фиксирован; путь установщика и аргументы передаются отдельно в окружении, а не подставляются в исполняемый текст. Установщик запускается через `Process.Start` с `UseShellExecute=false`, поэтому подменённый файл не получает автоматическое повышение даже при запросе администратора в его манифесте.

Подтверждение готовности идёт по случайно именованному каналу с доступом текущего пользователя. Клиент проверяет PID сервера канала. Вспомогательный процесс проверяет PID и время создания родителя, доступность файла и ждёт разрешения. Подготовка и обмен ограничены тайм-аутами; ожидание завершения клиента — 120 секундами. Ошибка до передачи управления не отключает VPN; ошибка после завершения клиента показывается отдельным сообщением.

## Ограничения

- Нужен обычный рабочий стол Windows того же пользователя и сеанса. Запуск под другой административной учётной записью, повышенный Explorer, недоступный PowerShell или политика Constrained Language дают отказ, а не небезопасный запуск. Политики исполнения Windows не обходятся.
- Это закрытие наследования повышенных прав, а не проверка подлинности установщика. Защита от подмены в пределах обычных прав и проверка подписи/доверенного хеша остаются отдельной задачей.
- Проверки используют безвредный заменитель установщика. Настоящая установка/замена установленной версии этими тестами не выполняется.

## Проверка

После Release-сборки:

```powershell
.\build\Test-UpdateHandoff.ps1
# Повторить в терминале, открытом от имени администратора:
.\build\Test-UpdateHandoff.ps1 -RequireElevated
```

Три проверки рабочего стола запускаются отдельно от обычного CI, где Explorer может отсутствовать. Они проверяют SID/сеанс/обычные права дочернего процесса, ожидание родителя дольше прежних четырёх секунд и отказ при несовпадении личности родителя. Результаты: `artifacts/test-results/UpdateHandoff-normal.trx` и `UpdateHandoff-elevated.trx`. Остальные тесты запускаются через `build/Build.ps1 -Target Test`.

Платформенные основания: [CreateProcessWithTokenW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createprocesswithtokenw), [DuplicateTokenEx](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-duplicatetokenex), [CreateEnvironmentBlock](https://learn.microsoft.com/en-us/windows/win32/api/userenv/nf-userenv-createenvironmentblock).

## Результат проверки реализации — 31 августа 2026

Исход: `fixed` для наследования повышенных прав при запуске обновления; прежние исправления профилей, маршрутизации и подписок сохранены.

1. Просмотр изменений и `git diff --check` — пройдены. `dotnet build NothingVpn.sln -c Release --no-restore` — без ошибок и предупреждений.
2. `dotnet test tests/NothingVpn.Application.Tests/NothingVpn.Application.Tests.csproj -c Release --no-build --no-restore --filter "FullyQualifiedName~InstallerLaunchServiceTests"` — 11/11. Небезопасные токены и другие пользователи/сеансы отклоняются, пути с метасимволами остаются данными, повышенного запасного запуска нет.
3. `build/Test-UpdateHandoff.ps1` — 3/3; повторный запуск с `-RequireElevated` из действительно повышенного терминала — 3/3. В повышенном прогоне родитель: `Elevated=True`, `Administrator=True`, integrity 12288; потомок: тот же SID и сеанс, не администратор, medium integrity. Проверены ожидание выхода родителя и отклонение несовпадающего времени его создания.
4. `build/Build.ps1 -Target Test` — Release-сборка, 201 обычный тест и WPF smoke-test пройдены. Три desktop-теста в общем запуске намеренно пропущены и выполнены отдельно в обоих контекстах выше.

Независимый просмотр не обнаружил сохранившегося обхода повышения прав. Его запуск desktop-тестов внутри CodexSandboxOffline был заблокирован Constrained Language; это не использовалось как доказательство работоспособности. Успешные desktop-прогоны выполнены вне sandbox, под обычным пользователем и с подтверждённым UAC-повышением. Реальная установка обновления и интерактивный TUN-сеанс не запускались.
